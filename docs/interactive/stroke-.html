Technical Comparison & Structural Design Trade-offs

Disk page alignment, memory cache locality, and access geometries differ drastically between point lookups, chronological timeline traversals, and multi-dimensional spatial queries.

Feature / Property B-Tree B+-Tree R-Tree
Data Key Storage Stored in both internal and leaf nodes Stored only in leaf nodes; internal nodes store routing keys Leaf nodes contain spatial objects/MBRs; internal nodes contain bounding regions
Leaf Node Structure Independent leaf pages with data/pointers Linked sequentially as a Doubly Linked List Contains Minimum Bounding Rectangles (MBRs) and entry pointers
Range Search Efficiency Slow ($O(k \log N)$) requiring in-order tree traversal Optimal ($O(\log N + k)$); traverse to leaf then walk linked list N/A for linear keys; designed for 2D/3D bounding box range intersection
Disk / Page Fanout Moderate fanout; data values reduce number of keys per disk page Maximum fanout; internal pages hold only compact keys Variable; depends on spatial bounding box dimensions and overlap heuristics
Search Time Complexity $O(\log N)$ average/worst $O(\log N)$ deterministic (all leaf depth identical) $O(\log N)$ average, $O(N)$ worst case if bounding boxes heavily overlap
Document System Role Primary Key Index: Instant lookup for Note ID, User UUID, and tag key hashes. Timeline & Feed Index: Fast pagination, date ranges ("Notes created in July"), and sorted text searches. Spatial Canvas Workspace: Infinite canvas note placements, viewport clipping, and lasso region queries.
