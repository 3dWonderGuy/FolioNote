2/**
3 * =========================================================================================
4 * @file core/objects/object_action_registry.hpp
5 * @brief Registry Interface for Standard Canvas Object Actions and Stacking Operations
6 * =========================================================================================
7 *
8 * ARCHITECTURAL DESIGN & INVERSION OF CONTROL:
9 * --------------------------------------------
10 * ObjectActionRegistry centralizes universal canvas object operations within the `core/objects`
11 * domain, decoupling raw object geometry models from engine and session mutation state.
12 *
13 * Concrete implementation details, heavy upward subsystem dependencies (CanvasEngine,
14 * DocumentSession, CanvasPage, VideoObject, ImageObject, ClipboardManager), and platform
15 * headers are isolated inside `object_action_registry.cpp` to prevent compilation cascade
16 * bottlenecks across the engine and UI layers.
17 *
18 * 1. Default Universal Actions:
19 * The registry provides standard commands applicable to canvas objects:
20 * - Delete (order: 0, destructive): Removes object from page, records history, clears selection.
21 * - Bring to Front (order: 200): Shifts object to the highest rendering index.
22 * - Bring Forward (order: 210): Swaps object with immediate forward neighbor.
23 * - Send Backward (order: 220): Swaps object with immediate backward neighbor.
24 * - Send to Back (order: 230): Shifts object to index 0 (background plane).
25 * - Duplicate (order: 300): Clones active selection with spatial offset (+10mm, +10mm).
26 *
27 * 2. Virtual Hook Customization:
28 * CanvasObject exposes a lightweight virtual hook: `CustomizeActions(actions)`.
29 * Subclasses (e.g. AttachmentObject, TextBoxObject, Shapes) override this hook to
30 * inject domain-specific commands (e.g. "Open Attachment", "Locate / Re-link File")
31 * or modify default actions before display.
32 *
33 * 3. Sorting & Deterministic Layout:
34 * Actions are stably sorted by `ContextMenuItem::order` weight (ascending), ensuring
35 * predictable menu layouts across arbitrary object hierarchies.
36 */

58 * @brief Generates and returns the complete, ordered list of actions for a given canvas object.
59 *
60 * MATHEMATICAL & WORKING PROCESS:
61 * 1. Constructs standard universal actions with explicit sorting weights:
62 * - Delete:
63 * `page->RemoveObjectByUid(targetObj->uid)`
64 * Records atomic `RemoveObjectsCommand` into session history for undo/redo.
65 * Clears selection gizmo and marks viewport dirty (`needsFullRebake = true`).
66 * - Stacking & Layering (Z-Index):
67 * - Bring to Front: Moves target element to index `N - 1` where `N = objects.size()`.
68 * - Bring Forward (`ShiftFront`): If index `i < N - 1`, swaps element at `i` with `i + 1`.
69 * - Send Backward (`ShiftBack`): If index `i > 0`, swaps element at `i` with `i - 1`.
70 * - Send to Back: Moves target element to index `0`.
71 * - Duplicate:
72 * Invokes `session.DuplicateSelection(offsetMm = 10.0)` which applies translation
73 * matrix `T = [1, 0, +10; 0, 1, +10]` to all selected objects.
74 * 2. Invocates the virtual hook `obj->CustomizeActions(actions)` allowing the object
75 * subclass to inject domain-specific commands or adjust default properties.
76 * 3. Executes `std::stable_sort` on `order` to ensure deterministic visual layout.
77 *
78 * @param[in] obj Target CanvasObject clicked or selected.
79 * @param[in] page Active CanvasPage hosting the object.
80 * @param[in,out] engine CanvasEngine managing camera, selection gizmo, and viewport rebaking.
81 * @param[in,out] session DocumentSession managing undo/redo history and document operations.
82 * @return std::vector<ContextMenuItem> Ready-to-render, sorted list of interactive menu actions.
83 */
