2/**
3 * =========================================================================================
4 * @file core/objects/object_registry.hpp
5 * @brief Centralized Dynamic Object Factory, Reflection, and Metadata Registry for Canvas Objects
6 * =========================================================================================
7 *
8 * ARCHITECTURAL DESIGN & PURPOSE:
9 * -------------------------------
10 * ObjectRegistry establishes an Inversion-of-Control (IoC) dynamic factory and reflection
11 * registry for the FolioNote canvas object hierarchy.
12 *
13 * 1. Open-Closed Principle (SOLID):
14 * Subsystems like DocumentSession, BinarySerializer, and ClipboardManager no longer need
15 * to maintain monolithic `switch (obj->type)` or `if/else` ladders or include every
16 * concrete container header in the application.
17 *
18 * 2. Self-Registration via Translation Units:
19 * Each object container (e.g., AttachmentObject, InkContainer, ImageObject, VideoObject)
20 * registers its constructor factory function inside its own `.cpp` file during static
21 * initialization. New object types or plugins can be introduced with zero edits to
22 * existing storage or clipboard translation units.
23 *
24 * 3. Thread-Safe Global Access:
25 * All registration, introspection, and instantiation routines are synchronized via a
26 * shared mutex to support concurrent deserialization across worker thread pools.
27 */
