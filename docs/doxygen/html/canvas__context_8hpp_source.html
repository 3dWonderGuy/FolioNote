2/**
3 * =========================================================================================
4 * @file core/objects/canvas_context.hpp
5 * @brief Unified Environment Dependency Injection Context for Canvas Objects
6 * =========================================================================================
7 *
8 * ARCHITECTURAL DESIGN & PURPOSE:
9 * -------------------------------
10 * Solves deep subsystem coupling and cascading recompilation bottlenecks across the canvas hierarchy.
11 *
12 * 1. Zero Downcasting & Polymorphic Interaction:
13 * Callers operating on `std::shared_ptr<CanvasObject>` or `CanvasObject*` must never call
14 * `std::dynamic_pointer_cast`. All input interactions (clicks, double clicks, activation)
15 * dispatch polymorphically via virtual interaction methods like `OnPointerClick(const CanvasContext&)`.
16 *
17 * 2. Dependency Inversion & Subsystem Access:
18 * Instead of individual object headers directly including heavy application subsystems
19 * (`file_manager.hpp`, `canvas_engine.hpp`, `document_session.hpp`, `clipboard_manager.hpp`,
20 * `settings_manager.hpp`), this context forward-declares and wraps references/pointers to these
21 * core services.
22 *
23 * 3. Settings Manager Integration:
24 * Allows canvas objects to read application configuration and persist user preferences
25 * (e.g., default container dimensions, grid snapping, tool presets, media playback volume)
26 * through `ctx.settingsManager` without hard header dependencies.
27 *
28 * 4. Spatial & Modifier Telemetry:
29 * Carries the exact physical world coordinates (in millimeters), click cadence (single vs.
30 * double click), and active keyboard/input modifiers (Ctrl, Shift, Alt).
31 */
