2/**
3 * =========================================================================================
4 * @file app/actions/ui_action.hpp
5 * @brief Universal, Backend-Agnostic UI Action & Command Model for FolioNote
6 * =========================================================================================
7 *
8 * ARCHITECTURAL DESIGN & PURPOSE:
9 * --------------------------------
10 * UIAction is the fundamental command and interaction descriptor in FolioNote. It completely
11 * decouples command definition and execution from UI presentation:
12 *
13 * 1. Zero UI Engine Dependency:
14 * Uses pure standard C++20 (<string>, <functional>, <vector>, <cstdint>).
15 * Contains NO ImGui, OpenGL, or platform headers.
16 * This allows core engines, headless unit tests, and future UI frontends (such as
17 * ThorSVG, custom vector renderers, or a standalone ImGui UI builder) to define,
18 * inspect, and dispatch actions without any graphics backend coupling.
19 *
20 * 2. Unified Interaction Model:
21 * A single UIAction can simultaneously represent:
22 * - A button in the Ribbon bar or toolbar
23 * - An item in a right-click context menu
24 * - A row in a Command Palette / Actions search modal
25 * - A global keyboard accelerator / shortcut
26 * - A nested flyout submenu (via `subActions`)
27 *
28 * 3. Hierarchical Composition (Submenus):
29 * Actions can contain arbitrary levels of `subActions`. UI renderers recursively
30 * traverse this tree to produce cascading context menus, dropdown flyouts, or tool palettes.
31 *
32 * 4. Dynamic State Predicates:
33 * In addition to static flags (`isEnabled`, `isSticky`), actions support dynamic
34 * lambdas (`isEnabledFn`, `isCheckedFn`, `isVisibleFn`) evaluated per-frame to
35 * accurately reflect active application state.
36 */
37
