1. SYSTEM TOPOLOGY & RESPONSIBILITIES
--------------------------------------------------------------------------------
The canvas object architecture operates under a strict Inversion of Control
pattern to prevent compilation cascades and eliminate downcasting.

[DocumentSession]
      | (Strong Ownership)
      v
 [CanvasPage]
      | (Polymorphic Ownership)
      +---> std::vector<std::shared_ptr<CanvasObject>>
      |
      +---> [R-Tree Spatial Index] (AABBs indexed in world mm)

Entities:
  - CanvasObject:  Entity Blueprint (Pure World Millimeters, no engine coupling).
  - CanvasContext: Service Courier (Transient injection of subsystems).

2. CORE ABSTRACTIONS
--------------------------------------------------------------------------------
A. CanvasObject (canvas_object.hpp)
   The abstract base class for all drawable canvas elements.
   - Primary Units: Physical world millimeters (mm).
   - Invariants:
     * Never stores screen-pixel values or zoom-dependent state.
     * Contains cached AABB `bounds` updated via `UpdateBounds()`.
     * Does not directly include engine, session, or file management headers.
   - Key Virtual Hooks:
     * Render(BLContext& ctx, const Viewport& viewport) const
     * UpdateBounds()
     * BakeTransform()
     * CustomizeActions(std::vector<ContextMenuItem>& actions)
     * OnPointerClick(const CanvasContext& ctx) -> bool

B. CanvasContext (canvas_context.hpp)
   The dependency injection packet passed downward into virtual interaction hooks.
   - Subsystem References (Guaranteed non-null):
     * stateMachine : IInputStateMachine&
     * session      : DocumentSession&
     * engine       : CanvasEngine&
   - Subsystem Pointers (Optional / null-safe):
     * fileManager     : IFileManager*
     * clipboard       : IClipboard*
     * contextMenu     : IContextMenuManager*
     * settingsManager : ISettingsManager*
   - Event Telemetry:
     * worldX, worldY, isDoubleClick, modifiers

3. INTERACTION PIPELINE (POLYMORPHIC DISPATCH)
--------------------------------------------------------------------------------
Downcasting via std::dynamic_pointer_cast in input handlers is strictly forbidden.

Input Dispatch Flow:
  1. InputStateMachine (Mouse/Touch/Stylus) detects pointer contact.
  2. Canvas coordinates projected to world space: (worldX, worldY) mm.
  3. activePage->HitTestSingleClick() locates target CanvasObject.
  4. Dispatcher constructs transient CanvasContext:
         Folio::CanvasContext ctx{
             .stateMachine  = *this,
             .session       = session,
             .engine        = canvas,
             .fileManager   = nullptr,
             .clipboard     = &Folio::ClipboardManager::Instance(),
             .contextMenu   = nullptr,
             .worldX        = worldMm.x,
             .worldY        = worldMm.y,
             .isDoubleClick = isLastClickDouble,
             .modifiers     = clickModifiers
         };
  5. Dispatcher invokes `clickedObj->OnPointerClick(ctx)`.
  6. Return Values:
     * true:  Event consumed by object (e.g. video transport, file launch).
              Input machine halts selection and skips gizmo activation.
     * false: Event unhandled. Falls through to standard SelectionGizmo binding.

4. OBJECT ACTION REGISTRY & CONTEXT MENUS
--------------------------------------------------------------------------------
Right-click menus are built cooperatively via ObjectActionRegistry:
  1. Registry builds universal default actions:
     - Delete (order: 0, destructive)
     - Set as Background / Unlock (order: 190)
     - Bring to Front (order: 200)
     - Bring Forward  (order: 210)
     - Send Backward  (order: 220)
     - Send to Back   (order: 230)
     - Copy (order: 280)
     - Cut (order: 290)
     - Duplicate (order: 300)
  2. Registry invokes virtual hook: `obj->CustomizeActions(actions)`.
     - AttachmentObject: Injects "Open", "Locate/Relink", "Copy Path".
     - VideoObject:      Injects "Play/Pause", "Mute", "Reset Native Size".
     - ImageObject:      Injects "Reset 1:1 Size", "Save Image As...".
  3. Actions are deterministically sorted via std::stable_sort on `order`.

5. CONTAINER CATALOG & LIFECYCLE STATES
--------------------------------------------------------------------------------
[x] AttachmentObject (attachment_container/attachment_container.hpp/.cpp)
    - Fixed badge (chipW x chipH mm). Locked MoveOnly gizmo.
    - Double-click launches file via OpenFile().
[x] VideoObject (media/videos/video_container.hpp/.cpp)
    - libVLC decode frame blitting to BLImage. Aspect ratio strictly preserved.
    - Transport bar and YouTube poster thumbnail support.
[x] ShapeObject (primitives/shape_container.hpp/.cpp)
    - Procedural vector paths (Rect, Ellipse, Triangle, Star, Waves).
    - Custom hatching patterns and outline dash decomposition.
[x] ImageObject (media/images/image_container.hpp/.cpp)
    - Multi-format loader (PNG, JPEG, WebP, SVG, GIF animation).
    - 4096px RAM protection clamp and DPI-based physical millimeter mapping.
[-] InkContainer (ink_container/)
    - Vector ink stroke collection and centerline spline pipeline.
    - Active focus: ribbon polygon extrusion (StrokeOutlineBuilder).
[ ] TableObject (table_container.hpp)
    - Stubbed interface placeholder for Phase 2 structured grids.
6. DYNAMIC OBJECT REGISTRY & FACTORY (object_registry.hpp/.cpp)
--------------------------------------------------------------------------------
Provides dynamic object instantiation and type reflection without hardcoding
monolithic switch-case statements across serialization, copy-paste, and export:
  - Self-Registration: Concrete objects register at startup in their .cpp via:
      ObjectRegistry::Register<T>(type, "Name", "Icon", isConstructible);
  - Dynamic Instantiation:
      auto obj = ObjectRegistry::Create(type);
  - Introspection & Reflection:
      - HasType(type)
      - GetMetadata(type) -> ObjectTypeMetadata (name, icon, isConstructible)
      - GetAllRegisteredTypes()
